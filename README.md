# 今天晚饭吃什么

给它一句"我手头有什么"，它给你几道菜，每道菜配一条 B 站做饭视频。

纯后端服务，没有前端页面。输入是一句自然语言，比如：

> 我现在有番茄，豆腐，葱，请你推荐我今天晚上吃什么

输出是若干道菜，每道菜附一条视频链接——视频是按投币、点赞、播放量三个维度选出来的，不是搜索结果里的第一条。

> **状态：可用。** B 站检索与打分链路已实测跑通。

## 它是怎么工作的

```
用户输入
   │
   ▼
① LangChain + DeepSeek  →  菜名 JSON 数组
   │
   ▼
② B 站搜索（每个菜名独立并发检索）
   │
   ▼
③ 打分选优  →  每个菜只留一条最合适的视频
   │
   ▼
响应：菜名 + 用料 + 推荐理由 + 视频链接
```

三个环节互相独立，可以分别调试和测试——这正是它被拆成三段的原因。

**为什么要有第 ③ 步。** B 站搜"番茄炒蛋"，结果里混着探店 vlog、合集、纯音乐剪辑。这些视频播放量往往还很高。所以不能只看数据，得先用相关性把跑题的剔掉，剩下的才按数据排。

**为什么三个指标不能直接相加。** 一条视频的播放量通常是投币数的几十上百倍，直接加权的等于只看播放量。所以要先做归一化再加权。

**另外，B 站的搜索接口不返回投币数。** 只有播放量、点赞和收藏。所以程序实际上是两段式：先按播放量和点赞粗排，再对少量候选单独查一次详情拿投币。这也是接口耗时主要花在哪儿的地方。

## 快速开始

```bash
.venv/Scripts/python.exe -m pip install -r requirements.txt   # Windows
.venv/Scripts/python.exe main.py                              # 启动
```

用 PyCharm 的话，直接对着根目录的 `main.py` 点绿三角就行，效果一样。

想要改完代码自动重启，改用 uvicorn 命令：

```bash
.venv/Scripts/python.exe -m uvicorn main:app --reload
```

如果要让局域网里其它设备也能访问，把 `app/config.py` 里的 `app_host` 改成 `0.0.0.0`。

启动后打开 http://127.0.0.1:8000/docs 可以直接在浏览器里试接口（FastAPI 自带的交互文档）。

### 配置

在项目根目录的 `.env` 里填：

```ini
DEEPSEEK_API=你的密钥
DEEPSEEK_MODEL=deepseek-chat
```

DeepSeek 的接口是 OpenAI 兼容的，所以走 `langchain-openai` 就行，不用装单独的 SDK。

## API

### `POST /api/recommend`

**请求**

```json
{
  "query": "我现在有番茄，豆腐，葱，请你推荐我今天晚上吃什么"
}
```

**响应**

```json
{
  "query": "我现在有番茄，豆腐，葱，请你推荐我今天晚上吃什么",
  "dishes": [
    {
      "name": "番茄炒蛋",
      "reason": "番茄和葱都能用上，十分钟出锅，适合工作日晚饭",
      "ingredients_used": ["番茄", "葱"],
      "video": {
        "title": "番茄炒蛋，记住这三点，鸡蛋嫩滑不出水",
        "url": "https://www.bilibili.com/video/BV1xx411c7mD",
        "author": "某某厨房",
        "play": 1234567,
        "like": 89012,
        "coin": 34567,
        "score": 0.87
      }
    }
  ]
}
```

几点约定：

- `video` 可能是 `null`——某个菜在 B 站确实搜不到合适的视频时，不影响其它菜返回。
- `score` 是归一化加权后的综合分（投币 0.4 / 点赞 0.4 / 播放 0.2）再乘上标题与菜名的相关性，取值 0~1。**只用于同一道菜的多个候选之间比较，跨菜比没有意义**——每道菜的候选集不同，最高分总是接近 1。
- `play` / `like` / `coin` 是 B 站返回的原始数值，保留原样便于排查打分是否符合预期。

### `GET /health`

存活探针，返回 `{"status": "ok"}`。

## 目录结构

main.py          FastAPI 入口、路由注册、并发编排
app/
  config.py      配置与可调参数

## 已知问题

**B 站接口的风控。** 网页版搜索接口未登录可用，只需要先取一个 `buvid3` cookie，实测不需要 WBI 签名。但这是 B 站单方面说了算的东西，随时可能收紧——真收紧了就得改成带签名的请求，或者退一步直接返回 B 站搜索页链接。

**标题近似但仍可能是另一道菜。** 搜「番茄烧豆腐」可能返回标题为「番茄烧茄子」的视频：限定语对上了，主料没对上。现在靠相关性系数压低它的分数，但如果候选集里没有更好的，它仍会被选出来。这是这套启发式方法的固有短板，要根治得引入菜谱语义匹配。
